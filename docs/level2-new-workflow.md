## 1) الموجودات — Finding Instructions من الشيت

### 1.1 التعليمات التأسيسية للمدير الشخصي (تبويب «الهوية الشخصية والتطوير»)

تم استخراج **مصفوفة إرشادات الوكيل الذكي (المدير الشخصي التنفيذي) — 10 قواعد**،
وأُعيد ترميزها حرفيًا في `level2/protocols.py` (`AGENT_MATRIX`):

| # | القاعدة | الملخص |
|---|---|---|
| M1 | قاعدة البديلين فقط (أ/ب) | خياران رئيسيان + توصية واضحة — لا قوائم طويلة |
| M2 | قاعدة كفاية 70% يقين | القرار القابل للعكس يُحسم بـ 70% من المعلومات |
| M3 | بريف الصباح المركز | أولويتان + قرار واحد فقط — حفظ الطاقة للعمل العميق |
| M4 | الشفافية والامتناع عن التخمين | غير المسجل يُقال عنه «غير مسجل» — الثقة أولًا |
| M5 | قاعدة الـ 48 ساعة للخطوة المادية | كل قرار يلزمه إجراء مادي خلال 48 ساعة |
| M6 | فلترة المبادرات الجديدة | فكرة ⇒ صندوق الاحتمالات، لا مشروع جديد قبل إغلاق المفتوح |
| M7 | الدعم المباشر في المواجهات الصعبة | مسودات SBI هادئة بدل التأجيل |
| M8 | رقابة سقف المصروفات | كل التزام مالي يُفحص أثره (الأرقام المالية أزيلت من الشيت نفسه — احترمنا ذلك: لا بيانات مالية في Level 2) |
| M9 | المراجعة الأسبوعية (الجمعة) | قياس القرارات المحسومة ومؤشرات نقاط الضعف |
| M10 | مستوى L2 | تنفيذ داخلي قابل للعكس + تقرير؛ الخارج اقتراح دائمًا |

معها **بروتوكول سرعة القرار** (7 مراحل: فرز ASAP/ALAP ⇒ خياران ⇒ ALAP للغير قابل
للعكس ⇒ Premortem ⇒ Stop Rule ⇒ Execution Lock ⇒ مراجعة الجمعة) — مرمّز في
`DECISION_PROTOCOL`، و**ميثاق الطاقة** في `ENERGY_CHARTER`.

### 1.2 نقاط الضعف الـ 29 (تبويب «تعليمات تجاوز نقاط الضعف»)

كل نقطة ضعف مع: المحفّز المعتاد، التعليمة البديلة، السلوك المطلوب، الحد الأدنى
الأسبوعي، مؤشر النجاح — مرمّزة كاملة في `WEAKNESSES` (الكمالية، الحدود الشخصية،
تجنب المواجهة، ضعف التفويض، بطء الحسم، التسويف، متلازمة المحتال، تشتت الأولويات،
الحمل الذهني، القرارات المالية، حماية وقت العائلة، النوم/التعافي، ... إلخ).
→ اطلب من المدير: «أعاني من التسويف».

### 1.3 مكتبة العبارات التوجيهية (28 موقفًا)

عبارة جاهزة + ما يجب تجنبه لكل موقف (طلب مساعدة مفاجئ، مواجهة تأخير، حماية وقت
عائلي، رفع سعر، تعامل مع نقد...) — في `PHRASES`.
→ «عبارة لطلب مساعدة مفاجئ».

### 1.4 بروتوكول الهدوء والتعافي (تبويب «الهدوء والتأمل»)

بروتوكول الإرهاق عند الانخفاض (إيقاف غير الحرج 24 ساعة، مشي/تنفس 20 دقيقة، تقليل
الالتزامات...) + 15 تقنية تنفس/تأمل مع «متى تُستخدم» — في `EXHAUSTION_PROTOCOL`
و `CALM_TECHNIQUES`. → «طاقتي 3» يفعّل البروتوكول تلقائيًا.

### 1.5 الهوية (DISC & Enneagram)

SC (المستقر المنضبط) + النمط 5w6 (المحقق/حلّال المشكلات) + HBDI أزرق/أخضر ⇒
قواعد أسلوب الحوار مبنية عليها في `identity.py` (هدوء ودقة، أرقام لا صفات، سؤال
واحد حاسم، لا حماس مصطنع).

### 1.6 موجودات تشغيلية من الشيت (حالة النظام القديم)

من تبويبي «حالة الوكيل» و«محادثات الوكيل»:

| المشكلة الموثقة | الدليل | أثرها على القرار المعماري |
|---|---|---|
| تعطل مزود Kimi كليًا | HTTP 429 «account suspended due to insufficient balance» على كل الرسائل (21–22/09) | لا اعتماد حياة أو موت على أي مزود سحابي — الوضع الحتمي هو الأساس، والمزود اختياري |
| أخطاء استقبال تيليجرام | HTTP 502 Bad Gateway و409 Conflict متكررة في الـpolling | القناة الاحتياطية فقط، لا العمود الفقري |
| تعارضات كتابة الحالة | «تعارض كتابة: الملف على القرص v1118 بينما النسخة المقروءة v11» متكررة | كاتب واحد + كتابة ذرّية في `level2/state.py` |
| ترحيل التخزين المتكرر | Webhook ثم Direct Sheets API ثم v2.1... | مصدر حقيقة واحد محلي ثابت |
| تراكم المتأخرات | 25 مهمة مفتوحة منها 20 متأخرة (Executive_Brief) | البريف المركز (M1/M3) يمنع الغرق بالقوائم |

## 2) الجديد: معمارية Level 2 (المبنية والفاعلة الآن)

```
متصفح Chrome/Edge ──(مايك + Web Speech)──▶ server.py ──▶ agent.py ──▶ state.py (JSON محلي)
      ▲                                        │                │
      └──────────(نطق TTS)──────────────────────┘                ├── protocols.py  (تعليمات الشيت)
                                                                  ├── identity.py  (SC/5w6)
تيليجرام (خارج البيت) ──▶ telegram_bridge.py ──▶ نفس العقل ──────┘
                                              └── llm.py (اختياري: Ollama محلي أو OmniRoute)
```

- **حوار حي**: زر 🎙️ → كلامك نصًا → رد المدير → ينطقه صوتًا (عربي) — كله محلي.
- **استشارة**: 14 نية صوتية مغطية (بريف/مهام/قرارات/ضعف/طاقة/تأمل/عبارات/مراجعة...).
- **ذاكرة**: ملف JSON ذرّي + 7 نسخ دوّرة على قرصك — بديل كامل عن Sheets+Supabase.
- **استيراد تم**: 25 مهمة مفتوحة + 1 قرار + 2 انتظار من الشيت (بلا أرقام مالية).

### ما لا يُلغى أبدًا (حوكمة مستمرة من فلسفة النظام)

1. **مصدر حقيقة واحد** — الآن: `level2/data/level2_state.json` بكاتب واحد ذرّي.
2. **لا أثر خارجي ذاتي** — L2: داخلي + تقرير؛ الخارج موافقة بشرية.
3. **لا تخمين بيانات** (M4) — غير المسجل يُقال عنه غير مسجل.
4. **الخصوصية** — الحالة مستثناة من Git، لا أسماء مرضى ولا أرقام مالية في Level 2.
5. **التراجع متاح** — كل طبقة قديمة محذوفة من Git قابلة للاسترجاع (`git checkout main -- المسار`).

## 4) خطوات العمل في VS Code (بالترتيب)

1. **جرّب Level 2 أسبوعًا** (بلا أي حذف):
   ```bash
   python3 -m level2.server        # يوميًا من VS Code Terminal
   # أو مع نموذج محلي أغنى:
   LLM_BASE_URL=http://localhost:11434/v1 LLM_MODEL=qwen3:8b python3 -m level2.server
   ```
2. **أوقف النشر القديم** (المرحلة ص أعلاه).
3. **احذف بالدفعات** (أ ← ب ← ج ← د)، وبعد كل دفعة في VS Code Terminal:
   ```bash
   python3 -m pytest tests/ -q          # ما تبقى من اختبارات يجب أن يمر
   python3 -m level2.server             # Level 2 لا يتأثر أبدًا (صفر استيراد من القديم)
   ```
   الحذف من VS Code: انقر الملف ← Delete، أو من Terminal:
   `git rm connectors/supabase_client.py` … (الالتزام في Git اختياري للتاريخ فقط).
4. **حدّث `.env.example`** بحذف المتغيرات الميتة وإبقاء:
   ```
   TELEGRAM_BOT_TOKEN=      # اختياري — جسر تيليجرام
   LLM_BASE_URL=            # اختياري — نموذج محلي أو مزودك
   LLM_API_KEY=
   LLM_MODEL=
   ```
5. **(اختياري) مهمة تشغيل سريع في VS Code** — أضف إلى `.vscode/tasks.json`:
   ```json
   {"label": "Level 2 Manager", "type": "shell",
    "command": "python3 -m level2.server", "problemMatcher": []}
   ```
   ثم `Ctrl+Shift+B` لتشغيل المدير مباشرة.
