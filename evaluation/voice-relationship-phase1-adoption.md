# 📥 تقييم VOICE-RELATIONSHIP-001 Phase 1 وقرار التبني — 2026-08-21

> المصدر: مواصفة Voice Relationship Manager — Phase 1 (النظام الآخر). القرار: **تبني المنطق الحتمي كاملًا الآن + تجهيز الوكيل الحي لمرحلة الربط**. نُفّذ في v0.3.1.

## التقييم

### صائب ويستحق التبني فورًا
1. **نطاق Phase 1 منضبط تمامًا**: وارد فقط، لا انتحال شخصية، لا إجراء خارجي، لا تحويل رقم جوالك — أفضل طريقة لبدء مهارة صوتية عالية المخاطر.
2. **Data Minimization افتراضيًا** (ملخص منظم فقط، لا صوت خام ولا تفريغ كامل) — القرار الصحيح قانونيًا وتقنيًا.
3. **مسودات فقط إلى ActionQueue → PENDING_APPROVAL** — اتساق كامل مع بوابة C2 عندنا.
4. **Handoff كطلب وليس تحويلًا تلقائيًا**، و**الأمان السريري بلا تشخيص من مكالمة** — متسق مع حزمة Clinical Intelligence عندنا.
5. **فصل namespaces الكتابة** (voice_calls/contacts/tasks/waiting_for/decision_requests/handoff_requests) ومنع الكتابة في decisions/clinical/credentials — تطبيق مباشر لأقل امتياز.
6. **سيناريوهات اختبار A–E مع توقعات محددة** — حولناها إلى اختبارات حية فعلًا.

### فجوات عولجت عند النقل
| الفجوة | المعالجة عندنا |
|---|---|
| لا إعلان عن التوثيق/موافقة التسجيل (متطلب PDPL) | جملة الافتتاح الإلزامية تشمل: «مساعد ذكي» + «قد يُلخَّص هذا الاتصال» |
| `waiting_for` بحقول غير موائمة لـManager Loop عندنا | الإدراج بصيغة schema v2 كاملة (wid/status/expected_by/source=VOICE_CALL) |
| مورد يعد بإرسال شيء ≠ عميل محتمل | `follow_up_required` للعملاء فقط؛ المورد → waiting_for فقط |
| عرض المكالمات في البريف بلا آلية «عُرضت مرة» | وسم `briefed` بعد التوليد الناجح + ترجيح الأمني/التحويلات أولًا |
| الانهيار بعد الالتزام يبتلع المكالمات | الالتزام (briefed + snapshot) انتقل إلى ما **بعد** كتابة التقارير بنجاح |

### ملاحظات عربية تقنية اكتشفها الاختبار الحي
- «تجاهل» تحتوي «اهل» حرفيًا → أنماط التصنيف بحدود كلمات.
- «المنزلية» تفعّل نمط «ألم» → نمط الألم باستبعاد الحروف اللاحقة.

## ما نُفّذ في v0.3.1
- **مساحات جديدة في StateStore**: `voice_calls` · `contacts` · `handoff_requests`.
- **`engine/voice_call.py`**: المعالج الحتمي بعد المكالمة — تصنيف المتصل/النية، حقائق (مدينة/خدمة/موعد/إلحاح)، قوة العميل، كشف الحقن ورفضه وتوثيقه أمنيًا، Handoff، إنشاء contacts (upsert بالهاتف)، مهام معاودة الاتصال، waiting_for v2، عميل محتمل + **مسودة متابعة إلى طابور الاعتماد**، وidempotency بمعرف المكالمة.
- **بريف + لوحة**: قسم «📞 مكالمات تحتاج انتباهك» (مرة واحدة لكل مكالمة، الأمني أولًا).
- **`prompts/voice-relationship.md`**: عقل الوكيل الحي (هوية/PDPL/محادثة/أمان سريري/حقن) — جاهز لأي مزود صوت يدعم العربية.
- **أحداث تدقيق** بمسميات المواصفة: VOICE_CALL_COMPLETED · VOICE_TASK_CREATED · VOICE_WAITING_FOR_CREATED · VOICE_HANDOFF_REQUESTED + security_prompt_injection.

## نتائج الاختبارات الخمسة (حيّة على نظامنا)
| الاختبار | المتوقع | النتيجة |

## المؤجل (يحتاج منك قرارًا/حسابًا)
المكالمة الحية نفسها تحتاج: رقمًا تجريبيًا + مزود اتصال صوتي (مثل منصات SIP/Twilio أو غيرها) + STT/TTS عربي. المعالج جاهز لاستقبال مخرجات أي مزود عبر `voice_call.py ingest call.json`. Phase 2+ (ذاكرة المتصل، التحويل الحي، اعتماد تيليجرام) تُبنى فوق نفس الأساس.
