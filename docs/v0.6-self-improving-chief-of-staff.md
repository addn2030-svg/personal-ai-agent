# AI OS v0.6 — Self-Improving Chief of Staff

## North Star
Learn from repeated experience without silently changing safety-critical behavior.

The system separates four things that are often mixed together in AI agents:
1. **Facts/state** — current operational truth.
2. **Episodes** — what happened and what the outcome was.
3. **Behavior model** — inferred or confirmed preferences about how the owner works.
4. **Skills** — reusable procedures that can be versioned, tested, approved and rolled back.

## Learning loop

`Experience → Reflection → Lesson → Skill Candidate → Regression Tests → Risk Gate → Approval → Active Skill → Outcome Tracking → Revision/Retirement`

### Experience capture
`engine/reflection_engine.py` stores structured experiences in `data/self_improvement/experiences.jsonl`.
Useful triggers include repeated workflows, owner corrections, failed approaches, successful repeated procedures, and explicit feedback.

### Reflection
The deterministic reflection layer proposes a lesson when a pattern repeats, or when corrections/failures recur. It does not invent a skill by itself; it produces traceable evidence IDs.

### Procedural memory
`engine/skill_registry.py` creates versioned Markdown skills under `skills/generated/` and metadata in `data/self_improvement/skills.json`.
Every skill records its source experience IDs, risk tier, version, tests, uses and status.

### Progressive disclosure
`engine/skill_runtime.py` loads only ACTIVE skills relevant to the routed domain, keeping context small and avoiding unrelated procedural instructions.

## Risk model
- **LOW**: formatting, summarization, personal organization, report layout. Can be auto-approved only after >=90% regression pass. No external effects.
- **REVIEW**: administration, staff, communications, projects, finance. Requires explicit human approval before ACTIVE.
- **LOCKED**: clinical, health-safety, permissions, security, external execution. Never auto-activates.

External actions continue to use the existing approval/executor architecture. Self-improvement cannot bypass it.

## Behavioral model
`engine/behavior_model.py` stores owner preferences separately from skills. Inferences carry confidence and remain `INFERRED` until confirmed. Contradictory evidence changes them to `REVIEW_REQUIRED` instead of silently overwriting history.

## Human controls
`engine/skill_admin.py` provides pending review, approve, activate, reject and rollback actions. Sensitive skills require owner judgment even after perfect tests.

## Evaluation
`evaluation/self_improvement_cases.json` contains policy regression checks. `evaluation/test_self_improvement.py` smoke-tests the learning loop, approval gate and behavioral confirmation separation.

## Weekly review
`engine/self_review.py` writes `reports/self-improvement-latest.md` summarizing new lessons, pending skill changes, active skills and unconfirmed behavioral inferences.

## Integrated cycle
Run:

```bash
python3 engine/v06_cycle.py
```

It executes the existing v0.5 operational cycle, then reflection, then the self-improvement review. It does not activate review/locked skills and does not execute external side effects.

## Privacy boundaries
Do not persist patient-identifiable clinical details into generated skills, GitHub, behavioral memory or general episodic memory. Do not persist API keys, bot tokens, passwords or secrets. Use environment/local secret storage only.
