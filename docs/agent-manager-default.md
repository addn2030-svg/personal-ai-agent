# تفعيل "مدير الوكلاء" (Super Manager) كردّ افتراضي

هذا الملف يوثّق راية كانت موجودة في الكود بلا توثيق: `AI_SUPER_MANAGER_DEFAULT`.

## الفرق بين المسارين

| المسار | الملف | السلوك |
|---|---|---|
| **المسار السريع** (`telegram_bot_legacy`) | `connectors/telegram_bot_legacy.py` | ردّ مباشر من النموذج (Gemini/Bedrock) بلا تحليل قرار — هذا ما يعمل افتراضيًا اليوم على كل رسالة طبيعية. |
| **مدير الوكلاء** (`Super Manager`) | `connectors/super_manager.py` | تحليل مُسنَد بالأدلة: `SITUATION` → `CONFIRMED` / `INFERENCE` / `NEEDS_INPUT` → `DEPENDENCIES` → `DECISION_CRITERION` → `OPTIONS` → توصية صريحة. مصمَّم كـ"رئيس أركان" لا أرشيف. |

## كيف تُفعّله

بدون أي إعداد، تقدر تستدعي مدير الوكلاء يدويًا برسالة تبدأ بـ`مدير ` أو `manager `، أو
بالأمر `/manager <هدفك>`. `/manager_status` يعرض حالته، و`/manager_shadow` يجرّبه
بدون التأثير على الرد الحقيقي.

لجعله **الرد الافتراضي على كل رسالة طبيعية** (أي "استبدال" المسار السريع)، اضبط:

```
AI_SUPER_MANAGER_DEFAULT=1
```

- محليًا: في ملف `.env` (غير مرفوع لِGit).
- في الإنتاج (Railway): Service → Variables → أضف نفس المتغيّر، ثم أعد النشر (Redeploy)
  حتى تُقرأ القيمة الجديدة عند إقلاع الخدمة.

القيمة الافتراضية `0` (أو أي قيمة غير `1`) تُبقي المسار السريع كما هو — لا شيء يتغيّر
حتى تضبط الراية صراحةً.

## ملاحظة أمان

هذا تبديل سلوك ردّ فقط (قراءة/صياغة)، ولا يفتح صلاحيات كتابة جديدة: أي إجراء خارجي
(تقويم، رسائل، مدفوعات) يبقى خلف بوابة الاقتراح → المعاينة → الاعتماد → التنفيذ كما هي،
بلا علاقة بهذه الراية.
