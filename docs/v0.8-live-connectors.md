# AI OS v0.8 — Live Connectors

## Purpose
Connect Gmail, Google Calendar, Google Drive, GitHub and Telegram to the Unified Inbox so the Chief of Staff can answer **what changed?** from live sources.

## Security model
- Read-only scopes for Gmail, Calendar and Drive.
- Google OAuth client file and cached token stay under `secrets/` and are gitignored.
- GitHub PAT stays in `GITHUB_TOKEN`; never commit it.
- Telegram token stays in `TELEGRAM_BOT_TOKEN`; never commit it.
- No connector auto-sends, publishes, deletes, books or pays.
- Content that appears patient-identifying/clinical is classified `CLINICAL_PRIVATE` and redacted from the personal OS path.
- Source IDs, timestamps and links are stored as provenance metadata.

## One-time local setup
1. Install optional dependencies:
   `pip install -r requirements-connectors.txt`
2. In Google Cloud create an OAuth **Desktop app** with Gmail API, Calendar API and Drive API enabled.
3. Save the downloaded client JSON as `secrets/google-oauth-client.json`.
4. Set a fine-grained GitHub token locally:
   Windows PowerShell: `$env:GITHUB_TOKEN="..."`
5. Set Telegram token locally:
   `$env:TELEGRAM_BOT_TOKEN="..."`
6. First run opens Google consent in the browser and writes only the local cached token to `secrets/google-token.json`.

## Run
`python3 engine/v08_cycle.py`

The cycle performs live sync, writes normalized items to `unified_inbox`, updates connector health, and then runs the v0.7 trust/change intelligence cycle.

## Connector behavior
### Gmail
Reads recent non-spam/non-trash/non-promotional messages. Stores subject, sender, snippet, labels, date and Gmail message ID. Heuristics may classify REQUEST / DECISION / WAITING_FOR / CLINICAL_PRIVATE; otherwise items stay NEW for review.

### Calendar
Reads yesterday through the next 14 days. Stores event ID, title, start/end, update timestamp and link.

### Drive
Reads recently modified files and records file ID, name, MIME type, modification time and link. File metadata becomes DOCUMENT input; content ingestion remains provenance-first and can be added selectively.

### GitHub
Reads recent commits and open pull requests from `AI_OS_GITHUB_REPO` (default `addn2030-svg/personal-ai-agent`).

### Telegram
The existing bot remains the interaction channel. v0.8 adds a non-sending `getMe` health probe so Trust Dashboard knows whether the bot credential works.

## Environment variables
- `GOOGLE_OAUTH_CLIENT_FILE` optional override
- `GOOGLE_OAUTH_TOKEN_FILE` optional override
- `GITHUB_TOKEN`
- `AI_OS_GITHUB_REPO`
- `TELEGRAM_BOT_TOKEN`

## Important
ChatGPT connector access and the local agent are separate authorization surfaces. ChatGPT can access connected Gmail/Calendar/Drive/GitHub in-chat, while the local v0.8 runtime uses your own local OAuth/token files so it can run even when ChatGPT is not open.
