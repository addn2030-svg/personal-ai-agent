# Abdulrahman AI OS v0.5 — Core Architecture

## هدف الإصدار
تحويل مجموعة المحركات الحالية إلى نظام واحد منظم: Router → Agent → Permission Gate → Draft/Local Update → Approval Queue → Executor → Audit.

## ما أضيف
- `engine/orchestrator.py`: توجيه حتمي أولي حسب المجال.
- `engine/permissions.py`: مصفوفة صلاحيات مركزية؛ أي أثر خارجي يمر عبر Executor واعتماد بشري.
- `engine/memory.py`: ذاكرة عاملة + أحداث + حقائق طويلة المدى، مع بقاء `data/state.json` مصدر الحقيقة التشغيلي.
- `engine/rag.py`: فهرس RAG محلي مع provenance للمصادر المسموح بها فقط.
- `engine/observability.py`: لقطة صحة الوكيل وحالة المخزن والموافقات.
- `engine/evaluate.py`: اختبارات regression للتوجيه وبوابات الأمان.
- `engine/control_center.py`: لوحة موبايل موحدة.
- `engine/v05_cycle.py`: تشغيل كامل v0.5 في أمر واحد.
- `engine/telegram_smoke_test.py`: اختبار إرسال واحد للمالك دون طباعة التوكن أو chat id.

## أين تأتي المعلومات؟
### 1. مصدر الحقيقة التشغيلي
`data/state.json` — المهام، المشاريع، العملاء، القرارات، الانتظار، الموافقات، التعلم، OKRs، الطاقة والمالية.

### 2. سجل التدقيق
`data/audit.jsonl` — كل كتابة واعتماد وحدث مهم كسطر JSON مستقل.

### 3. النسخ الاحتياطية
`data/backups/state-*.json` — آخر خمس نسخ من الحالة.

### 4. صندوق الالتقاط
`data/inbox.csv` — ما يرد من أداة اليوم أو Telegram قبل الاستيراد إلى الحالة.

### 5. المعرفة والمصادر
- `knowledge_sources` داخل `data/state.json`.
- `materials/`, `docs/`, `prompts/`, `evaluation/` — ملفات محلية معتمدة.
- سجل الأصول في `asset_registry` داخل الحالة وتقرير `reports/registry-latest.html`.
- Google Sheets/Docs المعرفة حاليًا كروابط/أصول في `engine/asset_registry.py`; ليست نسخة كاملة محلية تلقائيًا إلا إذا تم استيرادها بواسطة جسور النظام.

### 6. ذاكرة v0.5
`data/memory/working.json`, `data/memory/episodic.jsonl`, `data/memory/semantic.jsonl`.

### 7. فهرس RAG
`data/rag-index.json` — مشتق من الملفات المحلية المسموح بها، ويحتفظ باسم المصدر ورقم chunk. لا يفهرس `.env` أو tokens أو backups أو audit/raw uploads افتراضيًا.

## سياسة الخصوصية
- أسرار التشغيل تبقى في environment variables أو ملفات محلية مستثناة من Git.
- البيانات السريرية والمالية لا تُرسل خارجيًا تلقائيًا.
- أي إرسال/نشر/حجز/دفع يحتاج اعتمادًا بشريًا ثم Executor.
