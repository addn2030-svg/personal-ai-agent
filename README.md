# Abdulrahman AI OS v0.4

نظام تشغيل شخصي بالذكاء الاصطناعي: وكيل رئيسي (Chief of Staff) + 6 مهارات، يقرأ من **مخزن حالة موحد** ويخرج بريفًا يوميًا ومراجعة أسبوعية وكشف أنماط، وكل إجراء خارجي يمر بـ**طابور اعتماد** مرتبط ببصمة المحتوى.

## الجديد في v0.4.1 (منهجية ILPC — Bob Pike Group)
- **منهجية تصميم مواد إلزامية** مدمجة في `prompts/personal-training.md`: EAT (تجربة←وعي←نظرية) · CPR (≤20 دقيقة/مشاركة كل 8 دقائق/مراجعة يقودها المتعلم) · 90/20/8 · أهداف قابلة للقياس وإستراتيجية تقييم قبل أي محتوى.
- **أمر الهيكل**: `python3 engine/learning_engine.py outline LP-001` يولّد هيكل ILPC لأي خطة.
- **أول مادة مكتملة**: `materials/lp-001-lean-six-sigma-ilpc.md` — Lean Six Sigma ببيانات القسم الحقيقية، وحالة التكامل النهائية هي تجربة «تأكيد واتساب الثلاثاء» التي اقترحها كاشف الأنماط (التعلم يغلق الحلقة مع النظام).

## الجديد في v0.4 (تبني بروتوكول التدريس الشخصي الإلزامي)
- **محرك التدريس التكيفي** (`engine/learning_engine.py`): خطط مواد تعلّم ← أجزاء بدرجات وأحكام تكيفية إلزامية (≥85/70–84/50–69/<50) ← خريطة إتقان لكل مفهوم (معرفة/استدلال/تطبيق + أعلام سوء فهم) ← تقييم نهائي بجدولة متباعدة مستقلة لكل مفهوم (1/3/7/14/30).
- **دورة حياة مراجعة كاملة** (SCHEDULED→DUE→PRESENTED→ANSWERED→SCORED→COMPLETED) — الإشعار ليس تعلمًا، وlearning_reviews منفصلة عن طابور الإجراءات.
- **بريف الصباح**: «📚 مراجعات تعلّم اليوم (N دقائق)» بسقف مراجعتين.
- **بروتوكول التدريس الحي**: `prompts/personal-training.md` (فرز QUICK/COURSE، أسئلة استرجاعية موثقة بمصادر، تغذية راجعة بمخطط إلزامي).

## الجديد في v0.3.1 (تبني Voice Relationship Manager — Phase 1)
- **مُعالج المكالمات الواردة** (`engine/voice_call.py`): تفريغ المكالمة → تصنيف المتصل والنية → ملخص منظم → StateStore (جهات اتصال، مهام معاودة، waiting_for v2، عملاء محتملون، طلبات تحويل) + **مسودة متابعة إلى طابور الاعتماد** — لا إرسال إطلاقًا.
- **حمايات صارمة**: لا تشخيص من مكالمة، كلام المتصل = محتوى غير موثوق (محاولات الحقن تُرفض وتوثق أمنيًا)، Data Minimization، وidempotency بمعرف المكالمة.
- **قسم 📞 مكالمات في البريف واللوحة** (مرة واحدة لكل مكالمة — الأمني أولًا).
- جاهز للربط بأي مزود صوتي لاحقًا: `python3 engine/voice_call.py demo A|B|C|D|E` أو `ingest call.json`.

## الجديد في v0.3 (تبني Manager Loop من v4.1.1 الخارجية)
- **حلقة المدير بدورتين** (`engine/manager.py`): سريعة كل 15 دقيقة (مسح حتمي للانتظار) + كاملة 06:00 بتوقيت الرياض (بريف + لوحة) — مع catch-up لو فوّت التشغيلة، وwrite-on-change.
- **waiting_for schema v2**: آلة حالات WAITING→OVERDUE، وإجراء متابعة واحد لكل عنصر متأخر (idempotent)، ومسودة متابعة جاهزة.
- **decision_requests**: طلب قرار رسمي (خيارات + مهلة) للمشاريع النشطة المتوقفة فعليًا — حله يسجل في سجل القرارات بمراجعة بعد 30 يومًا، والخيار «تحويل إلى متوقف» ينفَّذ فعليًا.
- **كشف تغيّر الحالة**: قسم «🔄 ما تغيّر منذ البريف السابق» (جديد/تغيّر حالة/أُغلق).

## الجديد في v0.2 (إصلاحات C1 + C2 من المراجعة المعمارية)
- **State Store موحد** (`data/state.json`): الكاتب الوحيد لكل البيانات القابلة للتغيير — كتابة ذرّية، رقم إصدار يرفض التعارض، نسخ احتياطية دوّارة (آخر 5)، وسجل تدقيق `data/audit.jsonl`. **الشيت أصبح صيغة استيراد/تصدير فقط.**
- **طابور الإجراءات + بوابة اعتماد**: مسودات المتابعة تُدرج تلقائيًا كإجراءات `PENDING_APPROVAL` في `reports/approvals-latest.html`، ولا تُعتمد إلا بأمر يحمل **بصمة SHA-256 لنصها** (`python3 engine/approve.py approve A-001 --hash ...`)، وتنتهي صلاحيته بعد 48 ساعة، ولا يتكرر أبدًا (idempotency).
- **تعفّن الانتظار**: كل ما تنتظره (رد عميل، تحرك مشروع) يُشتق في `waiting_for` ويظهر في البريف، وما تجاوز 14 يومًا يُرفع كقضية قرار.

## البنية
```text
abdulrahman-ai-os/
├── blueprint.md            ← وثيقة الفهم والمعمارية (ابدأ من هنا)
├── evaluation/             ← مراجعة معمارية مستقلة + ما نُفذ منها
├── update.bat / update.sh  ← نقرة واحدة: استيراد الصندوق + توليد اللوحة وفتحها
├── data/state.json         ← ⭐ مخزن الحالة الموحد (الكاتب الوحيد — إصلاح C1)
├── data/audit.jsonl        ← سجل التدقيق لكل كتابة واعتماد
├── data/backups/           ← نسخ دوّارة من الحالة (آخر 5)
├── data/master-sheet.xlsx  ← صيغة الاستيراد/التصدير (لم يعد المخزن الأساسي)
├── data/inbox.csv          ← مخرجات صندوق اليوم (تُستورد ثم تُؤرشف)
├── engine/
│   ├── store.py            ← State Store: كتابة ذرّية + إصدارات + تدقيق
│   ├── chief_of_staff.py   ← المحرك: يقرأ الحالة ويولّد التقارير + يدير طابور الإجراءات
│   ├── approve.py          ← بوابة الاعتماد البشرية (approve/reject/executed/expire)
│   ├── import_inbox.py     ← يستورد صندوق اليوم إلى الحالة
│   ├── migrate.py          ← ترحيل لمرة واحدة: الشيت → state.json
│   ├── render_html.py / render_approvals.py ← واجهات اللوحة والاعتماد
│   └── make_template.py    ← يعيد بناء قالب الشيت
├── tools/daily-inbox.html  ← أداة الإدخال: قل/اكتب → صنّف → CSV (تعمل دون اتصال)
├── reports/                ← dashboard-latest.html + approvals-latest.html + تقارير
└── prompts/                ← حزم أوامر الوكلاء للصق في ChatGPT/Claude/Gemini
```

## التشغيل
```bash
python3 engine/chief_of_staff.py
```
يتطلب Python 3 مع `openpyxl` فقط (`pip install openpyxl`). لا يحتاج إنترنت ولا مفاتيح API.

## لوحة القيادة (للحفظ على سطح المكتب)
`reports/dashboard-YYYY-MM-DD.html` — صفحة واحدة تجمع **البريف الصباحي + المراجعة الأسبوعية** بتبويبين:
- تعمل **دون إنترنت** (كل التنسيق مدمج داخلها) — نزّلها واحفظها على سطح المكتب وافتحها بأي متصفح.
- زر **🖨️ طباعة / PDF** أعلى اليمين، وأزرار **📋 نسخ** لمسودات الرسائل.
- شارة أعلى الصفحة تبيّن هل البيانات «تجريبية» أم «حقيقية» — تُضبط من سطر `DEMO = True` داخل `engine/chief_of_staff.py` (اجعلها `False` بعد نقل بياناتك).
- لتحديثها: حدّث الشيت ثم أعد تشغيل المحرك واحفظ النسخة الجديدة.

## الاستخدام في ChatGPT وVS Code
راجع `docs/using-the-agent.md` — جسر كامل بين محركك المحلي وعقل LLM:
- **ChatGPT:** مهمة «🧠 تصدير سياق ChatGPT» ← الصق `reports/chat-context.md` في Project مجهز بحزمة `prompts/chief-of-staff.md` ← بريف وتحليل قرارات وتغذية راجعة (مثال حوار حقيقي داخل الدليل).
- **VS Code:** مهام جاهزة بنقرة (`.vscode/tasks.json`): تحديث اللوحة، دورة سريعة، استيراد الصندوق، الاعتمادات، مراجعات التعلّم.

## تفعيل اختبار CI (خطوة واحدة بعد الاستنساخ)
ملف سير العمل جاهز في `docs/ci-workflow.yml`. لتفعيله: في صفحة المستودع على GitHub ← **Add file ← Create new file** ← المسار `.github/workflows/ci.yml` ← الصق محتوى `docs/ci-workflow.yml` ← Commit. (أو أنشئ رمز PAT بنطاق `workflow` ودفعه برمجيًا). بعدها يعمل اختبار الدخان تلقائيًا مع كل دفعة.

## دورة الاستخدام اليومية (الحلقة الكاملة)
1. **خلال اليوم:** افتح `tools/daily-inbox.html` — اكتب أو سجّل صوتك (ar-SA) → الأداة تفصل وتصنّف تلقائيًا (مهمة/فكرة/سريري/قرار)، تستخرج المواعيد («الأسبوع القادم»، «غدًا»...)، وترمّز المرضى → **💾 تنزيل inbox.csv** في مجلد `data`.
2. **نقرة واحدة:** `update.bat` (ويندوز) أو `./update.sh` (ماك/لينكس) — يستورد الصندوق إلى الشيت، يعيد توليد لوحة القيادة، ويفتحها.
3. اقرأ البريف → وافق/عدّل/ارفض → حدّث النتائج الفعلية في تبويب «قرارات» (وقود وكيل Decision Twin).

أو يدويًا: `python3 engine/import_inbox.py` ثم `python3 engine/chief_of_staff.py`.

## ملاحظات خصوصية
- تبويب «متابعة مرضى» **برموز مجهلة فقط** (P-10X) — لا أسماء ولا هويات.
- كل مخرج سريري = فرضية للمراجعة البشرية؛ القرار النهائي للممارس.
